# Protocole de collaboration JP-Hermes

Mode d'emploi commun de notre travail. Identifié par analyse des 60 derniers
jours (67 sessions, 6 700+ messages, 12,7M tokens, 2,15 USD — 12/07→11/08).

## Le cycle en 6 temps

1. **Scan** — JP apporte une source brute (lien, repo, PDF, idée) → filtrer, verdict.
2. **Jugement** — avis d'expert demandé, pas un résumé. Rejet net = propre (« bof » → alternative construite).
3. **Appropriation** — « en quoi cela peut nous aider ? » → la veille devient outil.
4. **Construction itérative** — lancer, corriger, relancer. Corrections TOUJOURS ciblées (« fais la dernière correction », jamais « refais tout »).
5. **Validation par l'épreuve** — benchmark, stress test, preuve 2-3 lignes puis EXÉCUTER. Chaque correction se rejoue à ~0,3¢.
6. **Industrialisation** — dès que ça marche : standard, kit, doc. Puis MÉTA : le système lui-même.

## Rythme observé

- 09h : briefs / méta-réflexion · 15h : production lourde · 20-21h : veille.
- Lundis + dimanches = jours forts ; samedi quasi vide. Semaine de 6 jours.

## Constantes

- Chaque correction de JP = événement d'apprentissage (taste + mémoire).
- Confiance = accès : Drive → kDrive → secrets → psychologie (persona).
- Deux postures : stratège (débats, arbitrages) et opérateur (micro-corrections, « go »).
- JP délègue sa mémoire puis AUDITE qu'elle fonctionne (bug d'historique signalé le 16/07).

## Frictions connues (à traiter)

- Compactions fréquentes dans les sessions >200 msgs → re-explications (« reprends le travail de mon thème »).
- Questions déjà traitées qui reviennent → consulter le RAG/session_search AVANT de répondre.
- Sessions webui sans titre → introuvables ensuite. Toujours titrer (Telegram le fait bien).
