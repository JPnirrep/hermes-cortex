# 5-architecte-agents — moteur: qwen3.7-max

1. Architecture technique réelle : déclencheur kDrive SANS webhook et orchestration
Le remote rclone « kdrive: » (WebDAV Infomaniak) ne poussant pas de webhook, le déclenchement automatique repose sur un cron cost-zéro exécutant un script de polling `rclone lsf` sur les dossiers `KLEIA-UP` et `Projet JP` toutes les 10 minutes (fourchette justifiée : 5 min sature l'API WebDAV, 15 min frustre Sandrina). Dès qu'un nouveau fichier (mail exporté, note vocale transcrit, markdown) est détecté par modification de timestamp, le script pousse l'événement à n8n 2.42 via un webhook local. n8n 2.42 agit comme le système nerveux périphérique : il ingère le brut, appelle MISTRAL pour le scoring (type « JEV » comme dans LIGNE-EDITO-REWRITTEN-20261005.md) et le filtrage de laïcité, puis formate les artefacts. Hermes, via sa board kanban intégrée (`hermes kanban`, tick 60s), agit comme le noyau cognitif. n8n injecte les tâches dans Hermes via CLI. Hermes ne gère pas les fichiers, il gère l'état d'avancement et le dispatch vers JP. La séparation est stricte : n8n fait le « moulinage » I/O et IA, Hermes maintient la vérité d'état pour le cerveau de JP.

2. La boucle fermée : renvoi d'état sans requête (Push)
Puisque Buffer/Notion sont rejetés pour complexité et que JP exige qu'un dispositif qui attend sa demande soit un échec, la façade unique doit être le serveur web LOCAL déjà présent dans semaine-41-travail (`server.py` + `index.html` + `app.js`). Ce serveur ne doit plus être éphémère. n8n, à chaque étape franchie (script généré, plan de tournage à cases validé, visuels CANVA_MCP terminés), met à jour `etat.yaml` et ajoute une entrée horodatée dans `journal.jsonl`. `server.py` lit ces fichiers en continu. Pour « pousser » l'information à JP (profil TDAH), `app.js` doit déclencher une notification native du navigateur (Web Push API) ou un son local dès que `etat.yaml` passe un statut à « prêt pour action ». Le plan de tournage à cases (HTML+PDF) est affiché directement dans l'interface avec des cases à cocher interactives qui, une fois cliquées, renvoient un POST à `server.py` pour mettre à jour `journal.jsonl`. Le calendrier d'avancement est une vue Gantt simple générée en JS pur depuis `donnees.yaml`, éliminant le besoin d'un outil tiers.

3. Le détecteur de panne PAR ÉTAGE
Chaque étage doit inclure son propre détecteur de panne, sans quoi la chaîne aveugle JP.
- Étage 1 (Polling kDrive) : Le script cron surveille le code de retour de `rclone` et la latence. Seuil d'alerte : 3 échecs consécutifs ou latence > 8 secondes. Canal : n8n reçoit un payload d'erreur et envoie un email critique à JP.
- Étage 2 (Moulinage MISTRAL / Cohérence) : n8n surveille la sortie de l'IA. Seuil : score JEV < 60/100 ou détection par regex de vocabulaire ésotérique/religieux (viol de la laïcité absolue). Canal : la tâche est bloquée, `etat.yaml` reçoit le tag `ce_qui_ne_me_va_pas : "Dérive tonale/ésotérique"`, et Hermes kanban marque la carte en rouge.
- Étage 3 (Serveur local `server.py`) : Un cron secondaire ping `localhost:port` toutes les 60 secondes. Seuil : 2 pings échoués. Canal : script de redémarrage systemd automatique + notification push sur le navigateur de JP si le serveur revient, ou email si le redémarrage échoue.

4. La persistance : mémoire CONTINUE et transverse
Les fragments de semaine-41-travail meurent actuellement en fin de semaine. Pour créer une mémoire transverse, le répertoire `/home/debian/workspace/sandrina-strategie/` doit être initialisé comme un dépôt Git local. À la fin de chaque semaine, un cron cost-zéro commit les `etat.yaml`, `donnees.yaml` et `journal.jsonl` avec un tag sémantique (ex: `semaine-41`). Les artefacts lourds (visuels 4x5, 9x16 de `production/mercredi-07/`) ne sont pas commités mais référencés. Le fichier `LISEZ-MOI` de chaque production, qui liste déjà les IDs kDrive et formats, devient la clé de voûte de l'indexation : `server.py` parse tous les `LISEZ-MOI` historiques pour offrir à JP une vue transverse de tous les assets disponibles, classés par facteurs d'agrandissement et IDs kDrive, transformant des fragments locaux en une base de données d'actifs pérenne.

5. Les 3 modes de défaillance silencieuse à prévenir d'urgence
- Fuite sémantique HSP : MISTRAL génère un texte grammaticalement correct mais injonctif ou ésotérique, trahissant la voix unique de Sandrina. Sans détection active (regex + prompt de scoring JEV strict), ce texte est poussé en production, détruisant la confiance de l'audience.
- Pourrissement silencieux du token WebDAV : Les clés API Infomaniak ont un TTL (fourchette estimée : 24h à 30j selon la config). Si le token rclone expire, le polling renvoie un dossier vide sans erreur fatale. n8n croit qu'il n'y a pas de nouveau dépôt de Sandrina. Le système s'endort silencieusement.
- Trou noir du `default_assignee` : La board kanban Hermes a un `default_assignee` VIDE. Si n8n pousse une tâche (ex: « Validation plan de montage Filmora Pro ») sans forcer l'assignation explicite à JP dans le payload CLI, la tâche entre dans le tick de 60s, n'est assignée à personne, et disparaît de la vue active de JP, aggravant sa douleur de « travailler à l'aveugle ».

6. Verdict : le MVP en 1 semaine + ce qu'on ne construit PAS
Le MVP de la semaine 1 se concentre sur la tuyauterie de l'ombre et la façade locale. On câble le cron rclone à n8n 2.42, on configure le prompt MISTRAL avec le filtre de laïcité et le scoring JEV, et on connecte n8n à `hermes kanban` en forçant l'assignation à JP. On stabilise `server.py` pour qu'il lise `etat.yaml` et pousse les notifications Web Push. On initialise Git pour la persistance.
Ce qu'on NE construit PAS : 
- Pas d'intégration Postiz (le conteneur n'est pas détecté, et JP a rejeté les outils de type Buffer, bien que la POSTIZ_API_KEY soit présente). 
- Pas d'API Filmora Pro directe (trop complexe, on se contente de générer le plan de montage textuel que JP lit en regardant son logiciel). 
- Pas de base de données SQL externe : les fichiers YAML/JSONL locaux, versionnés par Git et lus par le serveur Python, suffisent amplement à l'échelle de Kleia-up et respectent la contrainte cost-zéro pour les tâches planifiées.
